# Memory upkeep
User rule, 2026-11-01: keep only essential current context; delete what no longer helps.
- Before editing, read the affected memory and verify status against code, manifests, source documents and dated evidence.
- Replace stale statements in place. Do not append correction chains, duplicate old/new status, or keep completed launch prompts as active plans.
- Keep durable constraints, current decisions, unresolved blockers and short evidence links. Delete obsolete facts and redundant/irrelevant memories; update all active references in the same change. Keep unresolved acceptance tests until verified or explicitly dropped.
- Keep one canonical home per fact. Exact versions, IDs, logs, execution history and detailed results belong in source/evidence files, not repeated memory.
- Distinguish accepted, implemented, deployed and verified. A plan/YAML file is not runtime proof; stored checks are dated evidence, not a fresh live check.
- core is the short entry point. Use backticked mem:name links and focused topic files. Keep project rules local.
- After relevant work, reconcile affected memories before the final response. Run serena memories check; if unavailable, check every link target directly and report the limit.
- Preserve AI_LOG.md prompt history, original sources and protected docs/architecture/history/. Memory cleanup does not authorize deleting code, evidence or unrelated files. Remove obsolete task-created documents only when requested or clearly within cleanup scope.
